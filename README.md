# dsh-pighub

**PigHub（猪猪库）的 DeepSeek Harness 插件：**在侧边栏养一个猪圈。每天领一只猪猪，重复的升星，攒够了把猪拖到桌面上遛。

猪猪素材来自 PigHub 社区图库及其开源镜像，**在构建期就处理好并随包分发**：去白底、裁到猪身、判定默认会不会动、要不要描摹成 SVG，全部在 `npm run assets:build` 时完成，产物是包内普通文件。

**运行时不访问素材库**：不请求上游、不做图像计算、不占用户算力。署名与出处见 [assets/ATTRIBUTION.md](./assets/ATTRIBUTION.md)，内容按版本手动更新。

## 它长什么样

- **侧边栏入口**：PigHub 站内那只标准小猪，**保留原色彩**（逐色块描摹自 `pighub-1114`：粉身、玫红耳/腮、浅粉高光），镜像成朝右，与已有入口同尺寸。
- **猪圈面板**：左边带围栏的大正方形猪圈（`min(60vmin,560px)`）；右上像素风标题（手写 5×7 位图字模），其下「今日猪猪」；再往下是可排序、可按位置筛选的猪猪清单。
- **跟随 DSH 亮/暗色主题**：全部颜色走 `--dsw-alias-*` 令牌，猪圈草地与围栏用 `color-mix` 与背景令牌混色，所以换主题不用改一行代码，也不需要维护第二套配色。
- **设置按钮**在面板整体右上角：星级显示三档（关闭 / 默认 / 常驻）、素材库版本与来源、下一版候选池、数据目录。
- **每日一只**：一天抽一次，池子是本版本冻结库；重复获得同一只升一星，分别记录「首次获得」与「最近升星」。
- **抽取动画**：从你按下的按钮弹出（缩放回弹 + 火花），再旋转着飞进猪圈，**落点就是这只猪真实的落点**（不是估算，见「验证」里的 landGap）。
- **会动的猪**：自己游走、点一下有弹性回弹；游走模型**逐参数对齐桌面桌宠**（`lib/native/pet-window.cs`）——
  每只猪各自计时，**每 1.7 秒决策一次、72% 原地发呆**，动起来就**匀速走过去**（每秒 1 个身位），不是猛跳一下。
  **走动时面朝运动方向**（素材默认朝左，向右走才镜像），**而且是蹦跳不是平移**（外层位移弧 + 内层 squash & stretch）。
- **步长**：每次决策采样的步长是 **[1.65, 3.0) 个身位**（身位 = 这只猪自己的宽度），方向在 0–360° 里均匀取一个；
  但**一次决策最多走 1.7 个身位**——桌宠会在 1700 ms 后再决策、把「走到一半」截断，猪圈在同一个点上截断目标，
  时长与距离仍成正比（恒速）。
- **边界是挡住的，不是弹回来的**：撞到围栏就**夹在围栏上**（与桌宠撞到屏幕工作区同一条规则：夹取而非反弹），
  不再重掷方向，也不会把一步拆成碎步。
- **自由拖动**：按住拖动时**实时跟随指针**（影子与圈里那只同尺寸），拖动期间这只猪**暂停游走**；
  **松手即固定落点**并原地站稳约 6 秒，不会一放就自己走开；
  在猪圈里松手即把落脚点改成松手处。落在哪儿会写进 `state.json` 的 `pig.pos`，
  **下次打开面板一进来就在那个点**（第一帧先发呆，不会立刻弹走）。
- **逐只行为开关**：右键猪本体或列表行 → 「允许运动 / 保持静止」。静止的猪不再游走、不响应点击，但仍可拖动；开关存进 `state.json` 的 `pig.motion`，缺省回落素材判定。
- **猪圈容量 12**：超过就自动落进仓库，并提示「猪圈满了，先住进仓库了」——不静默丢猪。
- **按位置筛选**：清单上方 全部 / 猪圈 / 桌宠 / 库存 四档；**点库存行即放回猪圈**。
- **卡通围栏（有高度）**：围栏拆成远/近两层——远侧画在猪后面、近侧画在猪前面，走到底边的猪会被挡住一截，于是「猪在圈里」有了纵深。造型是自己画的 SVG（粗圆头立柱 + 两道横杆 + 描边 + 地面投影），不引第三方素材。
- **仓库小屋**：猪圈左下角的小房子，把小猪拖进去即收进库存——**隐藏且不再加载贴图**。位置三态：猪圈 / 桌宠 / 库存，互斥。
- **GIF 素材**：动图原样随包分发（去白/裁切/描摹都会把动画冻成静态图），构建期用 magic 判定，客户端直接交给浏览器播放。
- **桌面桌宠（Windows 原生窗口）**：把猪放到桌宠位后，插件会拉起一个**自建的原生顶层窗口**
  （WinForms + `WS_EX_LAYERED/TOPMOST/TOOLWINDOW/NOACTIVATE` + `UpdateLayeredWindow` 逐像素 alpha），
  猪**在整个 Windows 桌面上走动**，可以盖在任何应用窗口之上；透明像素不挡鼠标（`WM_NCHITTEST` 自己判 alpha）；
  **一个窗口画全部桌宠**；双击回猪圈、右键切运动。位置写进 `state.json` 的 `pig.desktopPos`。
  **走动时是蹦跳不是平移**：与猪圈同一节拍（283 ms）同一幅度（0.12 个身位）的位移弧，外加一层
  **以脚底为锚点**的 squash & stretch（纵向 0.94 ↔ 1.06、横向取倒数所以面积守恒）——
  落地压扁、最高点拉长、脚始终踩在同一条地线上；**站着不动时不缩放**。
  非 Windows 或取不到编译器时**回退到页面级浮层**（不报错）。首次运行会用系统自带 `csc.exe` 编译一次
  （约 1–3 秒，按源码哈希缓存）。
- **页面内桌宠**（回退路径）：把猪拖出猪圈即成为置顶浮层，可拖动；允许运动的猪会自己溜达（约三成落脚点落回猪圈），
  **拖回猪圈矩形内松手即回圈**（也可以双击回圈）。哪些猪在猪圈外，记录在 `state.json` 的 `pets` 里，清单上会标「桌宠」。
  **平台限制**：原生桌宠只在 Windows 上可用（v0.9.0 起）；其它平台自动回退到页面级浮层。
- **清单不标活死**：会不会动是行为开关，不是身份；清单只在「静止」时给一个提示标签，位置（库存 / 桌宠）照常标。

## 素材：冻结、逐图判定、定制切分

```text
assets/sources.json           候选池（从公开目录里挑出来的候选）
assets/judgements.json        逐图判定：kind(live/dead) + mood(cute/reject) + 裁切框 + 去白阈值 + 判定理由
assets/cards/selection.json   角色卡里通过可爱闸门的收编名单（cute 进包 / reject 只留档）
assets/manifest.json          冻结产物：上面三份 + 每张贴图的 sha256/bytes + assetVersion
```

构建：`npm run assets:build`。它有两条硬约束：**候选池里每一张都必须有判定**（少一条或多一条都直接失败），**每一张都必须有理由**。所以「逐图判定」是构建的前置条件，不是口号。

角色卡的批量入口是 `npm run cards:make`（`--append` 增量出样，不动已有判定）→ 逐张目检写进
`assets/cards/index.json` → `npm run cards:report` 生成判定表 → `npm run cards:select` 生成收编名单 →
`npm run assets:adopt` 收进冻结库。

**可爱闸门（硬约束）**：判定里还有一条 `mood` —— 只收 `cute`；血腥（獠牙撕咬 / 伤口 / 血）、身体恐怖（一具身体多张脸）、
惊悚造型一律 `reject`，不进包，连理由一起记进 `manifest.moodRejected`。没有 `mood` 或没写理由，构建直接失败。
扩包走 `npm run assets:adopt`：只增不改，把 `assets/cards/` 里通过闸门的卡收编进 `assets/img` 与清单
（校验指纹与字节数、幂等、拒收留档），老素材不会被重新冻结。

同一套流程里还有**矢量图化**：判定为平涂卡通的图会被描摹成自包含 SVG（量化 → 等值线 → 简化 → 路径），以 `data:image/svg+xml` 渲染，**放大不模糊**；场景/照片类整图保留位图，因为描出来只会更脏。是否描摹同样逐图记录在判定表里。

去白底在**构建期**完成（色键 / 框阵 / 补洞见 `lib/imaging.js`），产物就是包内的普通文件；运行时只剩两件事：读清单、发本地贴图。
早期版本曾在浏览器里用「同源代理 + canvas 漫水填充」做这件事，那条路已经拆掉——它要联网、要占用户算力，还依赖上游可用性，
与本插件的构建期约定相反。裁切框与阈值逐图不同，所以同一张源图在任何机器上切出同一个结果。

## 安装

```sh
dsh plugin --profile <你的 profile> add dsh-pighub
```

装完重启 DSH：Host 半负责数据与抽取，浏览器半在启动时进图。

**装完之后请再点一次侧边栏的 PigHub 入口。** 实测（6/6 次「卸载 → 安装 → 打开面板」）：
安装返回成功、素材路由已经 200，但主区域**不会自己重新挂载面板**，看起来就是一片空白；
点一次入口即恢复（点击后 1.06–1.18 s 画出来）。这是宿主槽位的行为，不是插件抛错——
逐轮读数见 `archive/verify-completion-and-stability.md` §3。

本插件已在真机（DSH 桌面版 / profile `desktop`）上装过并逐屏核验：侧边栏图标、猪圈面板与排版、
桌宠浮层与游走。那次核验暴露的三个「只有真机才会犯」的缺陷（宿主 `ToolDefinition.output` 必填、
围栏 SVG 只占猪圈宽 58.6%、统计行误用候选池计数）都已在 0.5.10 修掉，逐条数字见 CHANGELOG。

## 数据放在哪

所有本地数据都在用户主目录的 `/.PigHub/：

| 文件 | 内容 |
|---|---|
| `state.json` | 拥有哪些猪（含活/死判定与切分参数）、星级、首次获得与最近升星、每日抽取记录、**桌宠列表** |
| `catalog.json` | 下一版候选池的目录缓存（只有 id/标题/文件名/URL） |
| `prefs.json` | 排序偏好与星级显示档位 |

状态文件损坏时不会静默覆盖：原文改名为 `state.json.corrupt-<时间戳>` 留着，插件退回空状态继续可用。

## 三层一致：尺寸、运动、进出

猪有三个显示层——**猪圈本体**、**页面级浮层**（非 Windows 的回退路径）、**原生桌面窗口**（Windows）。
三层的尺寸与运动**用同一份口径**，不是各自拍脑袋：

| 量 | 口径 | 落在哪里 |
|---|---|---|
| 本体宽度 | `sizeRatio`（`assets/manifest.json`，按不透明面积归一化，中位数 **96 CSS px**） | 猪圈：CSS `width: sizeRatio px`；浮层：同一个值；原生：**sizeRatio × devicePixelRatio** 物理像素 |
| 决策间隔 | **1700 ms**，每只猪各自计时 | 三层一致 |
| 发呆概率 | **0.72** | 三层一致 |
| 单步距离 | **1.65–3.0 个身位**采样，**一次决策最多走 1.7 个身位**（速度 × 1.7 s） | 猪圈按「身位 ÷ 圈宽 × 100」换算成百分比、不缩放；原生按物理像素 |
| 移动速度 | **1 身位/秒** | 猪圈按「距离 ÷ 速度」算 CSS 过渡时长；原生每帧按速度逼近 |
| 朝向 | `dx > 0` 才朝右；素材默认朝左，向右走水平镜像 | 三层一致 |
| 边界 | **夹取**：撞到边缘就贴着走，不反弹 | 猪圈夹进活动区，原生夹进屏幕工作区 |
| 走动弹跳 | 位移弧 **283 ms / 0.12 身位**，叠一层纵向 **0.94 ↔ 1.06**、横向取倒数的缩放，**锚点在脚底**；只有走动才动 | 猪圈：CSS `pighub-travel` + `pighub-hop`；原生：`pet-window.cs` 的同一条 `hopUnit` 相位 + GDI+ 三行矩阵 |
| 随机数 | 每次决策恰好 3 个：发呆 → 角度 → 步长 | 猪圈同一顺序、同一数量（贴边不再重掷角度） |

> **一处已知未对齐**：页面级浮层（非 Windows 的回退路径）用的是同一套常量，但**没有 1.7 身位的一窗上限**，
> 且朝向在 `dx = 0` 时偏向右。它不在本轮范围（本轮只对齐猪圈本体），逐项差异见
> `archive/pen-pet-alignment.md` §2.2。

**进出连续**：从猪圈拖出去时，桌面上的落点就是松手点（实测误差 ≤ 2px）；拖回猪圈时，落点换算成圈内百分比
（也是松手处，不是回到原位）；往返前后尺寸不变。静止的猪同样会采纳新落点，只是不走动。
## 素材补全（逐角色卡）

池子里的猪来自上游社区图，**有一部分天生就是半身像**（构建期没有切坏它们，是源图如此）。
对检测出的「直切成残缺」的猪逐个补全，每只单独定参数、留 before/after。**现行清单以编码字段为准**：

| 模式（`completion.mode`） | 只数 | 卡 | 补了什么 |
|---|---|---|---|
| `contour-closure` | 9 | 255 / 27 / 341 / 379 / 659 / 865 / 868 / 1087 / 1099 | 切口之外**不复制像素**：用椭圆端帽把切口跨度闭合（端点切线平行于原轮廓）、端帽内取「原图最近的纯填色」平涂、沿新轮廓按猪自己的勾线色/线宽重描；底/顶切口另补 2 条圆底腿 |
| `body-graft` | 3 | 104 / 452 / 481 | 只有头的胸像：按头像自己的填色/轮廓色补**躯干椭圆 + 2 条圆底腿**，头像原样压在上面（头自己的轮廓盖住接缝），头像像素一个未改 |
| `head-swap` | 2 | 751 / 974 | 切掉原图黑边后把脸贴到**标准猪身体**上，切口 8px alpha ramp，脸往身体里挪 10px 后逐图搜 dy |

机器可读的同一份记录：写在 manifest 的 `completion` 字段（每只带 `mode` / `by` / `note` / `at`）。

**校验读数**（2026-11-13 实测，报告 `archive/verify-completion-and-stability.md`）：14 只的
bytes/sha256/size 与磁盘逐字节相符、sizeRatio 落在 68.52–102.95、`/pighub/asset/<file>` 全部 200 且字节数等于清单、
`scripts/audit-completeness.py` 无切边；接缝（±8 逐列/行中位亮度剖面的最大相邻台阶）13 只 ≤ 3.18，
**pighub-868 是 144.18（腹底一条横贯的深色直边，未修）**；**pighub-1099 是 3.18**（接缝处 0.00，底边是直线）。
> `audit-completeness.py` 通过**不等于**切口不外露：它的判据落在 bbox 最外一行/列，而补出来的腿会把 bbox 撑开，
> 切口于是变成内部边。判封口要同时看接缝台阶与 3 倍放大图（taste.md §Q.5）。

> **文档冲突（2026-11-13 核对）**：本节此前有两张互相矛盾的表，把 868/379/255 记成 `bottom-legs`、
> 341/865/659 记成 `side-body`、974 记成「未完成」。这三种写法在 manifest 里都不存在（974 已完成换头）。
> 按「以代码为准」的口径改成上面这一张。

## 猪圈视觉（2026-11-13 定稿）

正方形、四边平行、同栏高、**无景深无几何透视**的平涂卡通围栏：一张 SVG，四条边共用一张 (u,v) 图纸 + 4 个 transform。
每个颜色都走 `color-mix` 主题令牌，浅色主题下整体淡一档。设计定调与判据见 `archive/pen-design/DESIGN.md`。
## 与其他桌宠插件共存

插件市场上的桌宠（例如 [dsh-pet](https://www.npmjs.com/package/dsh-pet)）都是页面级浮层，所以按同一套既有约定来：容器 `pointer-events: none`、自有 z-index 层、样式标签与类名全带 `dsh-pighub` / `.pighub-` 前缀、尊重 `prefers-reduced-motion`。

补全产物与运行时稳定性另有三支探针（`_` 前缀，不进管线）：

- `scripts/_verify-completion.py`：14 只补全猪逐张量「来源轮廓 IoU / 接缝台阶 / audit 完整性 / 元数据 / 3 倍放大图」；
- `scripts/_probe-actor-tick.mjs`：把**发货 bundle 的 250 ms actor 回调真的跑起来**（结构测试把 setInterval 换成了空实现，
  回调里的路径零覆盖——`ReferenceError` 那类缺陷只有它能抓），并做「卸载重挂 20 次，活着的定时器数量不变」的累积检查；
- `scripts/_probe-assets.mjs` / `_probe-consistency.mjs` / `_probe-asseturl.mjs`：贴图 HTTP 200 与字节对账、
  id ↔ 文件名串号、URL 上 `?v=` 的幂等性。

界面另有一套**本地**验证台（不随仓库分发、不进 npm 包）：它按宿主契约把 `lib/client.js` 挂到普通页面上，并埋四个探针——

- **alpha**：把渲染出来的图重画到 canvas 逐像素读四角 alpha，证明白底真被抠掉；
- **motion**：4.2 秒前后各采一次落脚点，分别统计会动的猪 / 静止的猪 / 桌宠移动了多少只；
- **reveal**：自动点一次「今日猪猪」，采样动画阶段并比较落点与真身中心的像素差；
- **svg**：统计以 `data:image/svg+xml` 渲染的图数量，确认矢量化的就是那些图。

当前基线：`live=1/1 dead=0/4 pets=1/1`（验证台内部计数口径）、会动的猪四角 alpha 全 0、`landGapPx=0`、`svg=2`。

## 发布

走 **GitHub Actions + npm Trusted Publishing**，仓库里不放长期 token：`pack` job 无凭据校验 tag 与版本并跑全部测试，`publish` job 消费同一份 tarball，用 OIDC 换短期凭据发布并生成 provenance。npm 后台三项匹配（仓库 / `publish.yml` / `npm-publish`）任一不符都会被拒。
